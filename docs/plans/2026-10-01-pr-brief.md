# Development Plan: PR Brief
Packages: server, client (+ both @devdigest/shared copies) · Base: feat/pr-brief@c5f6a03 · Spec: specs/2026-10-01-pr-brief.md
Context pack: docs/plans/2026-10-01-pr-brief.context.md
Execution: multi-agent (chosen by the user)

## Goal
PR Brief card on top of Overview (banner, summary, Risk areas, Review focus deep-linking to Files changed). One model call per POST over pre-computed facts, stored in `pr_brief`, GET adds a stale flag.

## Out of scope
- Spec §3. No migration (`pr_brief` exists [F1]); no e2e/MCP.

## Decisions
- New `modules/brief/` mirrors `modules/onboarding/` - [F4][F5]
- LLM output schema loose (no `.max`); `normalizeBrief` clamps/drops (AC9 clamps, never re-asks) - [F5]
- Specs: per current-review agent (newest review first) call `projectContext.service.resolveForRun`, merge + de-dup by path, then the brief budget drops whole docs from the last. Status `missing|too_large|unreadable` -> `specs/unreadable`, `over_budget` -> `specs/over_budget`, detail "k of n" - [F8] / user
- Budget: NFR1 order + FR2 caps as written, no cap on `changed_symbols`; known limitation: huge PRs may exceed 8 000 est. tokens. The final estimate is always logged (per-request `estTokensIn` + generation line) so an overshoot is visible - user (Q2)
- AC17 deviation: never-answering POST verified by a service unit test with injected `timeoutMs`; a test pins `GENERATION_TIMEOUT_MS = 120_000`; "20 GETs < 300 ms" stays integration - user (Q3)
- Banner: new `BriefBanner` reusing `VERDICT_META` (exported via `VerdictBanner/index.ts`) + `CircularScore`; `VerdictBanner` unchanged - user (Q4)
- Per-request log lines from `onUsage` (attempt n); `prompt_assembled` gains feature `brief` + sections `changed_files`, `findings`, `linked_issue` - [F6][F7]
- Linked issue = first `#N` of stored body; `getIssue` raced vs 10 s - [F11]
- Changed ranges from hunk headers only (copy regex [F12])
- Client nav: `router.push(prDiffHref(...))` (new history entry, unlike [C9]); `prKeys.brief` not run-scoped (D8)
